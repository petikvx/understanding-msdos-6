cmd/recover/recover.asm — « rebuild an ms.dos directory »

RECOVER

Le dernier recours de la page FAT : si la racine est détruite, on invente un fichier par chaîne encore lisible. Ce n’est pas élégant. Ça sauve parfois des octets.

The FAT page’s last resort: if the root is destroyed, invent one file per chain still readable. It is not elegant. It sometimes saves bytes.

RECOVER A:

DécouverteDiscovery FILE0001.REC

Sans noms, il reste les chaînes FAT. RECOVER parcourt les clusters occupés, coupe aux mauvais, et crée des fichiers numérotés dans une racine neuve. Les sous-répertoires deviennent de la bouillie.

Without names, FAT chains remain. RECOVER walks busy clusters, cuts at bad ones, and creates numbered files in a fresh root. Subdirectories become mush.

IntermédiaireIntermediate vs CHKDSK /F

CHKDSK répare à partir des répertoires encore valides. RECOVER jette l’annuaire et repart de la table. À n’utiliser que si CHKDSK ne peut plus rien lire.

CHKDSK repairs from directories that are still valid. RECOVER throws away the directory and starts from the table. Use only if CHKDSK can no longer read anything.

TechniqueTechnical recproc.asm

Même vocabulaire que CHKDSK (EOFVAL, BADVAL, FCB interne). Les deux outils sont cousins ; RECOVER est le plus destructeur.

RECOVER FICHIER.TXT

DécouverteDiscovery Couper la chaîne au cluster mort Cut the chain at the dead cluster

Un seul fichier : on suit DIR_FIRST, on marque mauvais le cluster illisible, on tronque la taille. Le reste du fichier est perdu.

A single file: follow DIR_FIRST, mark the unreadable cluster bad, truncate the size. The rest of the file is gone.

IntermédiaireIntermediate M002 taille

20-Aug-91 : bug en ajustant la taille des fichiers récupérés. La taille dans le répertoire et la chaîne FAT devaient encore coincider après la coupe.

20-Aug-91: bug adjusting recovered file sizes. Directory size and FAT chain still had to match after the cut.

TechniqueTechnical M003 nibble FAT12

En marquant un cluster pair comme mauvais, RECOVER écrasait le nibble bas du suivant — exactement le piège de PACK (AND 0F000h). Le correctif est le même que dans le noyau.

FCB et SHARE

DécouverteDiscovery M001

RECOVER piochait un pointeur SFT dans un champ réservé du FCB. Sous DOS 5 sans SHARE, ce champ a changé de sens. Plus besoin de mettre à jour la SFT : elle est régénérée depuis le FCB.

RECOVER pulled an SFT pointer from a reserved FCB field. Under DOS 5 without SHARE, that field changed meaning. No need to update the SFT: it is rebuilt from the FCB.

IntermédiaireIntermediate FCBRegen

Même histoire que fcbio.asm : les 8 octets « CAVEAT PROGRAMMER » ne sont plus stables. Les vieux outils se brûlent.

Same story as fcbio.asm: the 8 “CAVEAT PROGRAMMER” bytes are no longer stable. Old tools get burned.

TechniqueTechnical 20-Aug-91

Trois correctifs le même jour (M001 SFT, M002 taille, M003 FAT12). RECOVER n’était plus aligné sur le noyau 5/6.
