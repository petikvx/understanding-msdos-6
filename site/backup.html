cmd/backup · cmd/restore — C, DOS 4, OS/2 cousin

BACKUP · RESTORE

Pas une image disque. Un gros sac BACKUP.001 et un index CONTROL.001. Les fichiers sont concaténés ; les noms, dates et attributs vivent dans le contrôle. RESTORE sait encore lire l’ancien format DOS ≤ 3.2.

Not a disk image. One big bag BACKUP.001 and an index CONTROL.001. Files are concatenated; names, dates and attributes live in the control file. RESTORE still reads the old DOS ≤ 3.2 format.

CONTROL.xxx + BACKUP.xxx

DécouverteDiscovery file-by-file, pas image

backup.c le dit noir sur blanc : « not an image type backup ». On peut formater la cible à la volée (/F, non documenté), journaliser (/L), ne prendre que l’archive (/M), ajouter (/A), filtrer date/heure. SUBST/JOIN sont refusés — comme FORMAT et DISKCOPY.

Un fichier trop gros pour une disquette est coupé : bit NOTLASTPART dans l’en-tête, séquence, offset dans BACKUP.xxx. La disquette suivante reprend.

backup.c says it plainly: “not an image type backup”. Target can be formatted on the fly (/F, undocumented), logged (/L), archive-only (/M), appended (/A), date/time filtered. SUBST/JOIN are refused — like FORMAT and DISKCOPY.

A file too big for one floppy is split: NOTLASTPART bit in the header, sequence, offset in BACKUP.xxx. The next floppy continues.

IntermédiaireIntermediate trois structures

Trois blocs empilés dans CONTROL.xxx (backup.h) :

  1. Disk_Header — identifiant 8 octets, n° de séquence 1–255, flag dernière cible 0xFF.
  2. Dir_Block — chemin 63 octets (sans lettre), nombre de fichiers, offset du bloc suivant ou 0xFFFFFFFF.
  3. File_Header — nom 8.3, flags (dernier fragment / succès / attributs étendus), taille, offset dans BACKUP.xxx, attribut, date, heure.

Les 63 octets ne sont pas un hasard : c’est la limite historique du chemin DOS (celle que XCOPY C02 a dû signaler).

Three blocks stacked in CONTROL.xxx (backup.h): Disk_Header, Dir_Block (63-byte path, no letter), File_Header (8.3, split flags, offset into BACKUP.xxx). The 63 bytes are the historic DOS path limit — the one XCOPY C02 had to report.

TechniqueTechnical backup.h 
struct Disk_Header {
    BYTE  DH_Length;
    BYTE  DH_Identifier[8];   /* "identifies disk as a backup" */
    BYTE  DH_Sequence;        /* 1-255 */
    BYTE  DH_reserved[128];
    BYTE  DH_LastDisk;        /* 0xFF if last target */
};
struct File_Header {
    BYTE  FH_Length;
    BYTE  FH_FName[12];
    BYTE  FH_Flags;           /* bit0 last part, bit1 ok, bit2 EA */
    DWORD FH_FLength;
    WORD  FH_FSequence;
    DWORD FH_BeginOffset;     /* into BACKUP.xxx */
    /* ... attr, time, date */
};

RESTORE lit deux époques

DécouverteDiscovery rtold.c · rtnew.c

Avant 3.3, BACKUP écrivait un fichier par fichier, préfixé. Depuis 3.3 (et CP/DOS 1.0 / OS/2), c’est le couple CONTROL+BACKUP. RESTORE détecte le format et branche : rtold.c / rtold1.c contre rtnew.c / rtnew1.c. /D (C01, 29-Jun-90) liste le contenu sans restaurer.

Before 3.3, BACKUP wrote one prefixed file per file. From 3.3 (and CP/DOS 1.0 / OS/2) it is the CONTROL+BACKUP pair. RESTORE detects the format and branches: rtold.c / rtold1.c versus rtnew.c / rtnew1.c. /D (C01, 29-Jun-90) lists contents without restoring.

IntermédiaireIntermediate /S /P /B /A /E /L /M /N

Filtres de restauration : sous-arbre, prompt si attributs changés, avant/après une date, avant/après une heure, seulement les modifiés, seulement les absents. SHARE est respecté — BACKUP ouvre en deny-write.

Restore filters: subtree, prompt if attributes changed, before/after a date, before/after a time, modified only, missing only. SHARE is honoured — BACKUP opens deny-write.

TechniqueTechnical version check DOS 4

L’en-tête de backup.c : « version checked to run ONLY on DOS version 4.00 ». Le binaire 6 est encore le code 4, avec doscalls.h OS/2 et le parseur commun. 14 fichiers C côté RESTORE : plus gros utilitaire « métier » de cmd/ après FDISK.

Header of backup.c: “version checked to run ONLY on DOS version 4.00”. The DOS 6 binary is still the 4.00 code, with OS/2 doscalls.h and the shared parser. 14 C files on the RESTORE side: the largest “business” utility in cmd/ after FDISK.

Le piège /Zp

DécouverteDiscovery structures packed

Le commentaire compile est un cri : « You MUST(!) use the PACKED option (/Zp) ». Sans ça, le compilateur aligne DH_Sequence et RESTORE lit n’importe quoi. Le format disque n’a pas de padding.

The compile comment is a shout: “You MUST(!) use the PACKED option (/Zp)”. Without it the compiler aligns DH_Sequence and RESTORE reads garbage. The on-disk format has no padding.

IntermédiaireIntermediate errorlevels

0 ok, 1 pas de fichiers, 2 conflit SHARE, 3 Ctrl-C, 4 erreur fatale. Les .BAT de nuit s’en servent. Même convention que XCOPY.

0 ok, 1 no files, 2 SHARE conflict, 3 Ctrl-C, 4 fatal. Nightly BATs rely on it. Same convention as XCOPY.

TechniqueTechnical cc /AS /Os /Zep /W3

/AS small model, /Os size, /Zep packed + enable extensions. LINK mapper+comsubs : couche d’appels DOS/OS2 partagée avec JOIN/SUBST.
