XCOPY · REPLACE · EXPAND

Trois façons de déplacer des octets sans cloner le média. XCOPY marche l’arbre et remplit la RAM. REPLACE ne touche que les homonymes. EXPAND décompresse les .EX_ de la disquette d’install — Lempel-Ziv, signature SZDD.

Three ways to move bytes without cloning the media. XCOPY walks the tree and fills RAM. REPLACE only touches namesakes. EXPAND decompresses the install-disk .EX_ files — Lempel-Ziv, SZDD signature.

XCOPY C:\SRC D:\DST /S /E

DécouverteDiscovery COPY qui sait les dossiers

Le COPY interne de COMMAND ne descend pas. XCOPY si : /S marche l’arbre, /E recrée même les répertoires vides. Sur un seul lecteur, il remplit d’abord toute la TPA de fichiers source, puis écrit — moins de « Insert source diskette » que COPY.

Ce n’est pas DISKCOPY : boot, FAT et clusters libres restent dehors. Ce n’est pas non plus BACKUP : les fichiers restent des fichiers DOS, lisibles sans RESTORE.

COMMAND’s internal COPY does not descend. XCOPY does: /S walks the tree, /E recreates even empty directories. On a single drive it first fills the whole TPA with source files, then writes — fewer “Insert source diskette” swaps than COPY.

It is not DISKCOPY: boot, FAT and free clusters stay out. It is not BACKUP either: files remain ordinary DOS files, readable without RESTORE.

Switches live in one OPTION_FLAG byte (xcopy.equ). The directory archive bit (FAT page) is a poor man’s backup marker: XCOPY /M then XCOPY /A the next day. APPEND is turned off while walking — otherwise the wrong file is opened.

TechniqueTechnical en-tête + 63 caractères

xcopy.asm : « WITH FULL MEMORY USE ». Chaque fichier lu devient un header chaîné (Next_Ptr / Before_Ptr, Continue_Info 0=entier, 1=petit fragment, 2=gros fichier, 3=EOF). Init vit dans un segment jetable (DSEG_INIT) pour laisser la place aux buffers.

xcopy.asm: “WITH FULL MEMORY USE”. Each file read becomes a chained header (Next_Ptr / Before_Ptr, Continue_Info 0=whole, 1=small fragment, 2=big file, 3=EOF). Init lives in a disposable segment (DSEG_INIT) to leave room for buffers.

; If /S and source+target paths would exceed 63 characters,
; files may silently not be copied. After the fix:
;   "Invalid path, not all directories/files copied"

C01 le même jour : racine pleine ou profondeur max — XCOPY s’arrêtait sans lister ce qui manquait. C09 (31JAN91) : l’INT 24 écrivait ERRORLEVEL avec le mauvais DS (porte de lecteur ouverte au départ). I00 : errorlevel 1 à tort si /S.

C01 the same day: full root or max depth — XCOPY stopped without listing what was missing. C09 (31JAN91): INT 24 wrote ERRORLEVEL with the wrong DS (drive door open at start). I00: spurious errorlevel 1 with /S.

REPLACE

DécouverteDiscovery mettre à jour, pas cloner

XCOPY crée. REPLACE ne remplace que les fichiers qui existent déjà sur la cible — sauf /A, qui n’ajoute que ceux qui n’y sont pas. Les deux à la fois sont interdits, comme /A+/S et /A+/U.

XCOPY creates. REPLACE only replaces files that already exist on the target — except /A, which only adds those that are not there. Both at once are forbidden, as are /A+/S and /A+/U.

IntermédiaireIntermediate /U /R /P /W

/U : seulement si la source est plus récente (date/heure de l’entrée répertoire). /R : écrase aussi les read-only. /S cherche l’homonyme dans tout l’arbre cible. Utilitaire C, DOS 5, même parseur commun que BACKUP/ATTRIB.

/U: only if the source is newer (directory date/time). /R: overwrite read-only too. /S looks for the namesake in the whole target tree. C utility, DOS 5, same shared parser as BACKUP/ATTRIB.

TechniqueTechnical cmd/replace/replace.c

FindFirst/FindNext + comparaison de noms 8.3. Pas de buffer « full memory » : un fichier à la fois. Moins de RAM, plus d’I/O, sémantique plus sûre pour une mise à jour d’appli.

EXPAND · signature SZDD

DécouverteDiscovery HIMEM.SY_ → HIMEM.SYS

Les disquettes Setup portent des fichiers compressés (dernier caractère remplacé par _). EXPAND les gonfle. Écrit par Steve Zeck et David Dickman, 1989–1991 — le même Lempel-Ziv que COMPRESS côté install.

Setup floppies carry compressed files (last character replaced by _). EXPAND inflates them. Written by Steve Zeck and David Dickman, 1989–1991 — the same Lempel-Ziv as COMPRESS on the install side.

IntermédiaireIntermediate anneau 4096

En-tête : 8 octets "SZDD\x88\xF0\x27\x33", algorithme 'A' (Lempel-Ziv), version 0, taille décompressée, date préservée. Buffer circulaire 4096, match max 16 octets. I/O jusqu’à 32 Ko, reculé par pas de 512 si malloc échoue.

Header: 8 bytes "SZDD\x88\xF0\x27\x33", algorithm 'A' (Lempel-Ziv), version 0, uncompressed size, date preserved. 4096-byte ring, match max 16 bytes. I/O up to 32 KB, stepped down by 512 if malloc fails.

TechniqueTechnical doslzexp.h 
#define szCompSig  "SZDD\x88\xf0\x27\x33"
#define cbRingBufMax    4096
#define cbStrMax        16
#define uchALG_LEMPEL_ZIV  ((UCHAR) 'A')

Fragmentation primitive : si le disque cible est plein, COMPRESS demande une autre disquette et continue sous le même nom. Pour décompresser, il faut recoller les morceaux (COPY /B a:f.1+a:f.2 f.out) avant EXPAND. Commentaire de expand.c : « occupies more than one floppy disk is handled in a primitive way ».

Primitive fragmentation: if the target disk is full, COMPRESS asks for another floppy and continues under the same name. To decompress, you must glue the pieces (COPY /B a:f.1+a:f.2 f.out) before EXPAND. Comment in expand.c: “occupies more than one floppy disk is handled in a primitive way”.
