boot/msboot.asm · bios/msload.asm

AmorçageBoot

Avant COMMAND.COM, avant INT 21h : 512 octets à l’adresse physique 07C00h doivent trouver IO.SYS, le poser en 00700h, et lui passer la main. Tout le reste du site naît de ce saut.

Before COMMAND.COM, before INT 21h: 512 bytes at physical 07C00h must find IO.SYS, place it at 00700h, and jump. The rest of this site is born from that jump.

  1. ROM BIOS — INIT matériel, INT 19h, piste 0 tête 0 secteur 1 → 0000:7C00, SP=0400h.
  2. msboot — lit le BPB, cherche IO.SYS dans la racine (copie à 500h).
  3. 3 secteurs — IBM_LOAD_SIZE = 3, premier cluster, contigus (déjà vu dans FAT · bootform).
  4. msload — suit la FAT pour le reste d’IO.SYS (DOS 4+ : un secteur FAT à la fois).
  5. SYSINIT — construit les DPB, lit CONFIG.SYS, charge HIMEM, COMMAND.COM.

ROM → 7C00h

DécouverteDiscovery Un seul secteur, tout le contrat One sector, the whole contract

Le BIOS ne connaît pas FAT. Il lit le premier secteur du disque d’amorçage et l’exécute. Si ce secteur ne trouve pas les fichiers système, message et halt — pas encore de DOS pour afficher autre chose.

The BIOS does not know FAT. It reads the first sector of the boot disk and runs it. If that sector cannot find the system files: a message and a halt — there is no DOS yet to print anything else.

IntermédiaireIntermediate CS=DS=ES=SS=0 · IP=7C00h

Le BPB est en tête (après le saut), comme sur la page FAT. FORMAT et SYS comptent sur PHYDRV à un offset fixe (fin du secteur) — Rev 3.2, LeeAc. On croit les boot 2.0 et 3.1, on doute du 3.0 (BPB décalé d’un octet sur certains disques IBM).

The BPB sits at the front (after the jump), as on the FAT page. FORMAT and SYS count on PHYDRV at a fixed offset (end of the sector) — Rev 3.2, LeeAc. We trust 2.0 and 3.1 boots, we distrust 3.0 (BPB off by one on some IBM disks).

TechniqueTechnical ORIGIN · DIR_OFF

Rev 3.31 : un JBE pourri pouvait lire trop de secteurs IO.SYS et écraser le boot ou la pile. DOS 4 ajoute le calcul 32 bits pour une partition primaire au-delà de 32 Mo.

Rev 3.31: a bogus JBE could read too many IO.SYS sectors and smash the boot or the stack. DOS 4 adds 32-bit math so a primary partition may start past 32 MB.

IO.SYS · premier cluster

DécouverteDiscovery Les fichiers système doivent être devant The system files must sit in front

SYS recopie IO.SYS / MSDOS.SYS de façon contiguë en tête des données. Le boot ne sait suivre qu’un tout petit bout de chaîne — d’où l’exigence « premier cluster, secteurs qui se suivent ».

SYS copies IO.SYS / MSDOS.SYS contiguously at the front of the data area. The boot can only follow a tiny bit of chain — hence “first cluster, consecutive sectors”.

IntermédiaireIntermediate AN006 : plus seulement le 1er cluster

Jusqu’à une certaine époque, tout IBMLOAD tenait dans le premier cluster. AN006 (avril 1990) lève cette restriction : msload sait enchaîner. Le boot lit toujours les 3 premiers secteurs pour démarrer le chargeur.

For a long time the whole IBMLOAD had to fit in the first cluster. AN006 (April 1990) lifts that: msload can walk the chain. The boot still reads the first 3 sectors to start the loader.

TechniqueTechnical même valeur que bootform.inc

IBMLOADSIZE equ 3 dans inc/bootform.inc doit rester égal à IBM_LOAD_SIZE ici. Le commentaire de msload : le boot devrait vérifier que IO.SYS commence bien au cluster 2 — « this would save a whole lot of time during system debugging ».

MSLOAD → SYSINIT

DécouverteDiscovery Le relais qui connaît la FAT The relay that knows FAT

Une fois les 3 secteurs en place, un vrai petit chargeur reprend : il lit la FAT (un secteur à la fois depuis DOS 4, pour aller plus vite et tenir en RAM), charge tout IO.SYS, puis SYSINIT prend le relais — CONFIG.SYS, puis COMMAND.COM.

Once the 3 sectors are in, a real little loader takes over: it reads the FAT (one sector at a time since DOS 4, faster and less RAM), loads all of IO.SYS, then SYSINIT takes over — CONFIG.SYS, then COMMAND.COM.

IntermédiaireIntermediate Limite 29 Ko levée

DOS 4 : calculs 32 bits, plus de plafond ~29 Ko sur IO.SYS, même message d’erreur que le boot si la lecture échoue. M056 : laisser l’INT 13 « fake » d’un RPL tranquille pour ne pas se faire marcher dessus par SYSINIT ni par le transient de COMMAND.

DOS 4: 32-bit math, no more ~29 KB cap on IO.SYS, same error path as the boot if a read fails. M056: leave an RPL’s fake INT 13 alone so SYSINIT and COMMAND’s transient do not step on it.

TechniqueTechnical bios/sysinit1.asm

SYSINIT ne demande plus de RAM à DOS pour DOS (M012) : il bricole arena_head juste au-dessus du noyau. MULTI_CONFIG : plusieurs blocs CONFIG. LoadDOSHiOrLow essaie la HMA (page HIMEM). Ensuite : CONFIG.SYS.

SYSINIT no longer asks DOS for RAM for DOS (M012): it patches arena_head just above the kernel. MULTI_CONFIG: several CONFIG blocks. LoadDOSHiOrLow tries the HMA (HIMEM page). Next: CONFIG.SYS.
