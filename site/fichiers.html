Fichiers ouverts Open files

La page FAT disait où sont les octets. Celle-ci dit comment un programme y touche : un petit numéro dans le PSP, une fiche cachée dans le noyau, puis UNPACK. Cliquez la machine — c’est un TYPE AUTOEXEC.BAT vu de l’intérieur.

The FAT page said where the bytes live. This one says how a program touches them: a small number in the PSP, a hidden card in the kernel, then UNPACK. Click the machine — it is TYPE AUTOEXEC.BAT from the inside.

    Handle · JFN

    Découverte Discovery Un numéro de vestiaire, pas le manteau A cloakroom ticket, not the coat

    Quand BASIC ou TYPE « ouvre » un fichier, DOS ne leur donne pas l’adresse du fichier sur le disque. Il rend un petit entier : 5, 6, 7… C’est un handle. Pour lire, on rend ce numéro ; DOS se souvient du reste.

    Ce numéro n’est valable que pour ce programme. Le même 5, chez un autre processus, désigne un autre fichier — ou rien.

    When BASIC or TYPE “opens” a file, DOS does not hand them the file’s disk address. It returns a small integer: 5, 6, 7… That is a handle. To read, you give the number back; DOS remembers the rest.

    The number is only valid for this program. The same 5 in another process names another file — or nothing.

    Intermédiaire Intermediate PDB_JFN_Table[BX] → SFN

    Chaque processus a un PSP (Process data block). Dedans, une table de 20 octets : PDB_JFN_Table. Le handle est un index dans cette table. La case contient un System File Number (SFN), ou FFh si elle est libre.

    À partir de DOS 3.3 on peut agrandir la table (AH=67h, $ExtHandle) : alors PDB_JFN_Pointer et PDB_JFN_Length désignent un tableau ailleurs. On ne peut pas descendre sous 20 (FilPerProc).

    Every process has a PSP (Process data block). Inside it, a 20-byte table: PDB_JFN_Table. The handle is an index into that table. The slot holds a System File Number (SFN), or FFh if it is free.

    From DOS 3.3 the table can grow (AH=67h, $ExtHandle): then PDB_JFN_Pointer and PDB_JFN_Length point at an array elsewhere. It cannot shrink below 20 (FilPerProc).

    SFT

    Découverte Discovery La vraie fiche, dans le bureau de DOS The real card, in DOS’s office

    Le handle n’est qu’un ticket. La fiche complète — nom 8.3, premier cluster, position de lecture, taille, mode d’ouverture — vit dans une table système, partagée par tous les programmes : la System File Table.

    Deux programmes peuvent tenir le même ticket interne (même SFT, sf_ref_count > 1) après un DUP ou un héritage père → fils. Fermer une copie ne ferme le fichier que lorsque le compteur tombe à zéro.

    The handle is only a ticket. The full card — 8.3 name, first cluster, read position, size, open mode — lives in a system table shared by every program: the System File Table.

    Two programs can hold the same internal ticket (same SFT, sf_ref_count > 1) after a DUP or parent→child inheritance. Closing one copy only closes the file when the count hits zero.

    Intermédiaire Intermediate sf_firclus relie à la page FAT

    Les SFT sont allouées par blocs chaînés (SFLink, SFCount). Par défaut DOS n’en crée que sf_default_number = 5 — une par handle standard. FILES=20 dans CONFIG.SYS ajoute d’autres blocs. D’où le message « Too many open files » alors que le JFN a encore de la place : c’est la SFT qui est pleine.

    SFTs are allocated in chained blocks (SFLink, SFCount). By default DOS only creates sf_default_number = 5 — one per standard handle. FILES=20 in CONFIG.SYS appends more blocks. Hence “Too many open files” while the JFN still has room: the SFT is full.

    Technique Technical SFFromSFN · sf_busy = −1

    SFFromSFN ne fait pas SFT[BX] : il soustrait SFCount à chaque bloc jusqu’à tomber dans le bon, puis BX × SIZE sf_entry + SFTable. Fin de chaîne : SFLink.offset = −1.

    SFFromSFN is not SFT[BX]: it subtracts SFCount at each block until it lands in the right one, then BX × SIZE sf_entry + SFTable. End of chain: SFLink.offset = −1.

    OPEN · INT 21h AH=3Dh

    Découverte Discovery Réserver une case, puis remplir la fiche Reserve a slot, then fill in the card

    Ouvrir, ce n’est pas encore lire. DOS cherche le nom dans les répertoires (ceux de la page FAT), réserve une SFT et un handle, copie le premier cluster sur la fiche, et rend le numéro. Si le nom n’existe pas : erreur 2. Si plus de cases : erreur 4.

    Opening is not reading yet. DOS looks up the name in the directories (the FAT page), reserves an SFT and a handle, copies the first cluster onto the card, and returns the number. If the name does not exist: error 2. If no slots left: error 4.

    Intermédiaire Intermediate Access + sharing dans AL

    Le bas de AL est le mode d’accès (filemode.inc) : 0 lecture, 1 écriture, 2 les deux. Le haut est le partage (DOS 3+) : compatibilité, deny-write, deny-none… Le bit 80h signifie « ne pas hériter au fils » (sf_no_inherit).

    The low nibble of AL is the access mode (filemode.inc): 0 read, 1 write, 2 both. The high nibble is sharing (DOS 3+): compatibility, deny-write, deny-none… Bit 80h means “do not inherit to the child” (sf_no_inherit).

    Lire, écrire, se positionner Read, write, seek

    Découverte Discovery DOS se souvient de la page où vous en étiez DOS remembers which page you were on

    Vous dites « lis 512 octets du handle 5 ». DOS sait déjà où vous vous êtes arrêtés la dernière fois (sf_position), retrouve le bon cluster, copie les octets dans votre tampon, et avance le signet. Écrire fait la même promenade, puis peut ALLOCATE un cluster de plus.

    You say “read 512 bytes from handle 5”. DOS already knows where you left off (sf_position), finds the right cluster, copies bytes into your buffer, and moves the bookmark. A write takes the same walk, then may ALLOCATE one more cluster.

    Intermédiaire Intermediate sf_lstclus, le raccourci

    Suivre la FAT depuis le cluster 2 à chaque READ serait cruel. La SFT retient le dernier cluster visité (sf_lstclus) et son index dans le fichier (sf_cluspos). Si vous reculez (LSEEK vers le début), DOS jette le cache et repart de sf_firclus.

    LSEEK (AH=42h) ne touche pas le disque : il ne fait que recaler sf_position — début, courant, ou fin (sf_size).

    Walking the FAT from cluster 2 on every READ would be cruel. The SFT remembers the last cluster visited (sf_lstclus) and its index in the file (sf_cluspos). If you seek backwards, DOS drops the cache and restarts from sf_firclus.

    LSEEK (AH=42h) does not touch the disk: it only resets sf_position — start, current, or end (sf_size).

    CLOSE · INT 21h AH=3Eh

    Découverte Discovery Rendre le ticket, ranger la fiche Hand back the ticket, file the card

    Fermer, c’est dire à DOS : je n’ai plus besoin du numéro 5. Le ticket redevient libre. Si personne d’autre ne tient la fiche, DOS écrit sur le disque la nouvelle taille et la date, et libère la SFT.

    Closing means telling DOS: I no longer need number 5. The ticket becomes free. If nobody else holds the card, DOS writes the new size and date to disk, and frees the SFT.

    Intermédiaire Intermediate Le handle meurt avant la SFT The handle dies before the SFT

    $Close écrit FFh dans le JFN puis appelle DOS_CLOSE. Le commentaire est explicite : même si la mise à jour du répertoire échoue, le handle reste fermé. On ne peut pas « réessayer » avec le même 5 — il faudrait rouvrir.

    $Commit (AH=68h) flush les tampons sans rendre le handle. Un commentaire BUGBUG de JGL doute qu’il mette vraiment à jour l’entrée de répertoire.

    $Close writes FFh into the JFN then calls DOS_CLOSE. The comment is explicit: even if the directory update fails, the handle stays closed. You cannot “retry” with the same 5 — you would have to reopen.

    $Commit (AH=68h) flushes buffers without releasing the handle. A BUGBUG comment by JGL doubts that it really updates the directory entry.

    FCB

    Découverte Discovery L’ancienne façon : le programme garde la fiche The old way: the program holds the card

    Avant les handles (DOS 2), le programme remplissait lui-même un File Control Block de 37 octets : lecteur, nom 8.3, taille d’enregistrement, numéro d’enregistrement. DOS n’avait pas de ticket à rendre — la fiche était chez vous, dans votre PSP (PDB_FCB1, PDB_FCB2) ou sur votre pile.

    MS-DOS 6 sait encore le faire. Beaucoup de vieux .COM s’en servent. C’est pour cela que le PSP réserve toujours de la place pour deux FCB par défaut.

    Before handles (DOS 2), the program itself filled a 37-byte File Control Block: drive, 8.3 name, record size, record number. DOS had no ticket to return — the card lived in your program, in your PSP (PDB_FCB1, PDB_FCB2) or on your stack.

    MS-DOS 6 still knows how. Plenty of old .COM files use it. That is why the PSP still reserves space for two default FCBs.

    Intermédiaire Intermediate En coulisse, une SFT quand même Behind the curtain, an SFT anyway

    Handle

    1 octet dans le PSP. La vérité est dans la SFT noyau. On peut hériter, dupliquer, protéger.

    1 byte in the PSP. The truth is in the kernel SFT. You can inherit, duplicate, protect.

    FCB

    37 octets chez l’utilisateur. DOS régénère une SFT à chaque appel (FCBRegen, SFTFromFCB) et y pose le bit sf_isfcb.

    37 bytes in user space. DOS rebuilds an SFT on every call (FCBRegen, SFTFromFCB) and sets sf_isfcb.

    Les 8 octets « réservés » du FCB (marqués CAVEAT PROGRAMMER dans cpmfcb.inc) cachent assez d’état pour reconnecter la SFT. Un programme qui les écrase casse l’I/O — d’où l’avertissement.

    The 8 “reserved” FCB bytes (marked CAVEAT PROGRAMMER in cpmfcb.inc) hide enough state to reconnect the SFT. A program that overwrites them breaks I/O — hence the warning.

    Technique Technical « Brain damaged programs »

    L’en-tête de fcbio.asm (MZ, décembre 1983) est un des plus savoureux du dépôt : certains programmes ferment le même FCB plusieurs fois ; d’autres écrivent dans un FCB déjà fermé. DOS 6 rend toujours OK sur un close répété, et EOF sur un I/O post-close.

    The header of fcbio.asm (MZ, December 1983) is one of the tastiest in the tree: some programs close the same FCB more than once; others write to an already closed FCB. DOS 6 always returns OK on a repeated close, and EOF on post-close I/O.

    Ces cinq-là ne pointent souvent vers aucun cluster : sf_flags a le bit devid_device (80h), et sf_devptr vise l’en-tête du pilote caractère. C’est le même bit ATTR_DEVICE que GETPATH pose en mémoire — jamais sur le disque (voir FAT · attributs).

    Those five often point at no cluster at all: sf_flags has devid_device (80h), and sf_devptr aims at the character driver header. That is the same ATTR_DEVICE bit GETPATH sets in memory — never on disk (see FAT · attributes).

    Redirecting > FILE.TXT is closing handle 1 and aiming it at a disk SFT. COMMAND.COM does that before running the line.

    Technique Technical filemode.inc

    Dup, héritage, FILES= Dup, inherit, FILES=

    Découverte Discovery Photocopier un ticket Photocopying a ticket

    DUP donne un second numéro pour le même fichier. Les deux partagent la position de lecture. Quand un programme lance un autre programme, le fils reçoit une copie de tous les tickets du père — sauf ceux marqués « ne pas hériter ». C’est ainsi que le fils écrit encore à l’écran sans l’avoir ouvert.

    DUP issues a second number for the same file. Both share the read position. When a program launches another, the child gets a copy of every parent ticket — except those marked “do not inherit”. That is how the child still writes to the screen without opening it.

    Intermédiaire Intermediate FILES= · trop de fichiers ouverts

    Deux plafonds distincts, souvent confondus :

    • le JFN du processus (20, ou plus via $ExtHandle) ;
    • la SFT globale (FILES= dans CONFIG.SYS, 5 par défaut).

    Un compilateur qui ouvre 30 fichiers échoue donc parfois alors que son JFN a été agrandi : il manque des SFT. Inversement, 8 processus × 5 handles standard saturent déjà une petite table.

    Two distinct ceilings, often mixed up:

    • the process JFN (20, or more via $ExtHandle);
    • the global SFT (FILES= in CONFIG.SYS, 5 by default).

    A compiler that opens 30 files can therefore fail after its JFN was grown: there are not enough SFTs. Conversely, 8 processes × 5 standard handles already fill a small table.

    Technique Technical $Dup · $ExtHandle · SHARE

    $Dup / $Dup2 : JFNFree (ou le handle cible pour Dup2), copie du SFN, INC sf_ref_count. $ExtHandle refuse toute valeur < 20, plafonne à 65534 (65535 est réservé comme marqueur busy). SHARE, s’il est chargé, s’accroche via JShare pour fusionner deux SFT identiques au moment de l’open (ShCol, appelé juste avant le Sys_Ret_OK de $Open).

    $Dup / $Dup2: JFNFree (or the target handle for Dup2), copy the SFN, INC sf_ref_count. $ExtHandle rejects anything < 20, caps at 65534 (65535 is reserved as the busy marker). SHARE, if loaded, hooks through JShare to collapse two identical SFTs at open time (ShCol, called just before $Open’s Sys_Ret_OK).
