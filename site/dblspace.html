inc/magicdrv.inc · dos/rom.asm

DoubleSpace

MagicDrv dans le code : un gros fichier (Compressed Volume File) qui se fait passer pour un disque. DOS continue de voir des clusters FAT ; le pilote comprime derrière. ALLOCATE a un crochet pour dire non si le FAT dit oui mais qu’il n’y a plus d’air comprimé.

MagicDrv in the source: a large file (Compressed Volume File) pretending to be a disk. DOS still sees FAT clusters; the driver compresses behind. ALLOCATE has a hook to say no if the FAT says yes but compressed free space is gone.

Un fichier qui est un volume

DécouverteDiscovery DBLSPACE.000

H: héberge le fichier compressé ; C: est l’illusion montée par le driver. CHKDSK / FORMAT voient C: comme un FAT normal — jusqu’à ce que l’espace « réel » soit épuisé plus tôt.

H: hosts the compressed file; C: is the illusion the driver mounts. CHKDSK / FORMAT see C: as a normal FAT — until “real” space runs out sooner.

IntermédiaireIntermediate MD_BPB · PLAIN_BPB

magicdrv.inc : en tête du CVF, un BPB (même champs que A_BPB) puis des extensions MagicDrv. Les premiers noms de champs ont changé — le commentaire le dit.

magicdrv.inc: at the start of the CVF, a BPB (same fields as A_BPB) then MagicDrv extras. Early field names changed — the comment says so.

TechniqueTechnical INT 2Fh 4A11h

MAGICPATCH

DécouverteDiscovery Le FAT peut mentir sur l’espace The FAT can lie about space

Un fichier de 1 octet prend un cluster logique entier, mais quelques centaines d’octets compressés. L’inverse aussi : un fichier incompressible « mange » plus que la FAT ne croit. D’où le patch dans ALLOCATE.

A 1-byte file takes a whole logical cluster, but only a few hundred compressed bytes. The reverse too: an incompressible file “eats” more than the FAT thinks. Hence the patch in ALLOCATE.

IntermédiaireIntermediate callmagic

On ne peut pas faire un far call avec fixups (ROMDOS / Hidos). callmagic simule un RETF vers dosdata:magicpatch. Sans patch, CLC et on continue.

A far call with fixups is forbidden (ROMDOS / Hidos). callmagic simulates a RETF to dosdata:magicpatch. With no patch, CLC and carry on.

TechniqueTechnical 7/5/92 scottq

Commentaire dans rom.asm : « fail allocations if the FAT would allow allocation, but the free space for compressed data would not. » Date : 5 juillet 1992.

Correspondance des lecteurs

DécouverteDiscovery MD_DRIVE_MAP

INT 2Fh AX=4A11h, fonction 1 : qui est le hôte, qui est le compressé. SMARTDRV (doubleb/) et CHKDSK s’en servent pour ne pas cacher deux fois le même secteur.

INT 2Fh AX=4A11h, function 1: which is host, which is compressed. SMARTDRV (doubleb/) and CHKDSK use it so as not to cache the same sector twice.

IntermédiaireIntermediate Stacker

SMARTDRV a aussi stacker.asm : le concurrent. DOS 6.22 passera à DriveSpace après le procès Stac — le crochet MAGICPATCH reste le même genre d’idée.

SMARTDRV also has stacker.asm: the competitor. DOS 6.22 will move to DriveSpace after the Stac lawsuit — the MAGICPATCH hook stays the same kind of idea.

TechniqueTechnical CVF ≠ partition

FDISK ne voit qu’une partition hôte. Le « C: de 200 Mo » n’existe pas dans la table MBR. C’est pour ça qu’un UNFORMAT / FDISK malheureux sur H: détruit tout le château de cartes.

FDISK only sees a host partition. The “200 MB C:” is not in the MBR table. That is why a clumsy UNFORMAT / FDISK on H: knocks the whole house of cards down.
