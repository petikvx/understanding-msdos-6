CHKDSK

L’inspecteur de la page FAT : il reconstruit en mémoire une carte de chaque cluster, confronte les chaînes des répertoires, et propose de ramasser les maillons perdus dans FILE0000.CHK.

The inspector for the FAT page: it rebuilds an in-memory map of every cluster, checks directory chains, and offers to gather lost links into FILE0000.CHK.

FATMAP

DécouverteDiscovery Une photocopie de la table, pour compter A photocopy of the table, to count

CHKDSK ne fait pas confiance au dpb_free_cnt du noyau. Il se fait sa propre carte (FATMAP) : pour chaque cluster, « vu dans un fichier », « libre », « mauvais ». Deux passes si besoin.

CHKDSK does not trust the kernel’s dpb_free_cnt. It builds its own map (FATMAP): for each cluster, “seen in a file”, “free”, “bad”. Two passes if needed.

IntermédiaireIntermediate BIGFAT · EOFVAL · BADVAL

Même seuil 12/16 bits que le noyau. EOFVAL / BADVAL reprennent FF8/FFF7. DIRTYFAT : on a modifié la table (après /F). FRAGMENT compte les sauts de chaîne — le rapport « contains n non-contiguous blocks ».

Same 12/16-bit threshold as the kernel. EOFVAL / BADVAL reuse FF8/FFF7. DIRTYFAT: we changed the table (after /F). FRAGMENT counts chain jumps — the “contains n non-contiguous blocks” report.

Clusters perdus Lost clusters

DécouverteDiscovery FILE0000.CHK

Occupés dans la FAT, absents de tout répertoire : un programme est mort au milieu d’une écriture (page cycle de vie). /F les enchaîne en fichiers dans la racine. Sans /F, CHKDSK ne fait que compter (ORPHCNT, ORPHSIZ).

Busy in the FAT, absent from every directory: a program died mid-write (life cycle page). /F chains them into files in the root. Without /F, CHKDSK only counts (ORPHCNT, ORPHSIZ).

IntermédiaireIntermediate ORPHFCB

Les orphelins sont créés via un FCB interne (ORPHFCB, extension dans ORPHEXT) — l’API antique de la page Fichiers, plus simple ici qu’un handle. DOFIX / HAVFIX décident si l’on écrit.

Orphans are created through an internal FCB (ORPHFCB, extension in ORPHEXT) — the old API from the Files page, simpler here than a handle. DOFIX / HAVFIX decide whether we write.

TechniqueTechnical SECONDPASS

Première passe : marquer les chaînes des répertoires. Seconde : ce qui reste occupé et non marqué est orphelin. Commentaire dans chkproc.asm : les fichiers « plus bas » peuvent apparaître comme lost clusters si on gère mal l’ordre.

First pass: mark directory chains. Second: whatever is still busy and unmarked is orphaned. Comment in chkproc.asm: files “further down” can look like lost clusters if order is handled badly.

Cross-links

DécouverteDiscovery Deux fichiers, le même cluster Two files, the same cluster

La FAT dit « suivant = 47 » pour deux chaînes différentes. Écrire dans l’un détruit l’autre. CHKDSK le signale (CROSSCNT) ; la réparation est plus délicate que pour un orphelin.

The FAT says “next = 47” for two different chains. Writing one destroys the other. CHKDSK reports it (CROSSCNT); repair is thornier than for an orphan.

IntermédiaireIntermediate CROSSLOOK

Pendant le parcours d’une chaîne, CROSSCHK regarde si le cluster était déjà marqué dans FATMAP. NZ → CROSSLINK, incrément de ISCROSS, message CROSS_arg.

While walking a chain, CROSSCHK asks whether the cluster was already marked in FATMAP. NZ → CROSSLINK, increment ISCROSS, message CROSS_arg.
