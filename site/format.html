FORMAT

L’outil qui pose le décor de la page FAT : secteur d’amorçage, FAT vides, racine vide. Sous MS-DOS 6, par défaut, il ne rase plus toute la zone données — d’où UNFORMAT.

The tool that sets the FAT page’s scenery: boot sector, empty FATs, empty root. Under MS-DOS 6, by default it no longer wipes the whole data area — hence UNFORMAT.

Safe format Safe format

DécouverteDiscovery Les fichiers ne sont pas vraiment effacés The files are not really erased

DOS 5/6 : FORMAT sauve assez d’informations (et laisse les clusters de données) pour qu’UNFORMAT reconstruise l’ancien volume. /U (unconditional) revient à l’ancien comportement destructeur. C’est le même principe que DIRFREE E5h : on marque, on n’écrase pas.

DOS 5/6: FORMAT saves enough information (and leaves data clusters) that UNFORMAT can rebuild the old volume. /U (unconditional) is the old destructive behaviour. Same idea as DIRFREE E5h: we mark, we do not overwrite.

TechniqueTechnical dskfrmt.asm

Le formatage « bas niveau » des pistes (disquette) est dans dskfrmt.asm via INT 13h. Sur disque dur, on ne reformate généralement pas les secteurs : on réécrit boot + FAT + racine. MSG_FMT_FAT_ERROR si l’écriture de la FAT échoue.

Low-level track format (floppy) is in dskfrmt.asm via INT 13h. On a hard disk we usually do not reformat sectors: we rewrite boot + FAT + root. MSG_FMT_FAT_ERROR if writing the FAT fails.

FAT clusters 0/1 get the media descriptor. The rest is zero (free). The root is full of 00 (end of directory, not E5).

IntermédiaireIntermediate PHYDRV · numéro de série

Le boot écrit doit coller à ce que msboot attend : PHYDRV au bon offset, BPB 2.0/4.x, pas le layout 3.0. Le numéro de série (DWORD) est tiré de la date/heure. EXT_SYSTEM_ID reçoit souvent FAT12 / FAT16.

The written boot must match what msboot expects: PHYDRV at the right offset, BPB 2.0/4.x, not the 3.0 layout. The serial (DWORD) comes from the date/time. EXT_SYSTEM_ID often gets FAT12 / FAT16.

FORMAT A: /S — une disquette qui démarre

DécouverteDiscovery /S = System

FORMAT tout seul prépare un volume vide (boot + FAT + racine). Au prochain allumage, le BIOS lit le secteur 0, ne trouve pas le DOS, et s’arrête : « Non-System disk ».

/S ajoute après ce décor les trois fichiers sans lesquels il n’y a pas d’invite :

  1. IO.SYS — le BIOS disque + SYSINIT (premier fichier de la racine).
  2. MSDOS.SYS — le noyau (INT 21h, FAT…).
  3. COMMAND.COM — l’invite A>.

FORMAT les prend sur le disque d’où tu lances la commande (souvent C:), les écrit au début de la zone données de la cible, et pose un secteur de boot qui sait les trouver. Tu obtiens une disquette de dépannage : boot sur A:, invite, sans Windows ni disque dur.

Plain FORMAT prepares an empty volume (boot + FAT + root). At next power-on the BIOS reads sector 0, does not find DOS, and stops: “Non-System disk”.

/S then adds the three files without which there is no prompt:

  1. IO.SYS — disk BIOS + SYSINIT (first file in the root).
  2. MSDOS.SYS — the kernel (INT 21h, FAT…).
  3. COMMAND.COM — the A> prompt.

FORMAT takes them from the disk you launched it from (often C:), writes them at the start of the target data area, and plants a boot sector that knows how to find them. You get a rescue floppy: boot from A:, prompt, no Windows or hard disk required.

IntermédiaireIntermediate pourquoi « premiers clusters, collés »

Le secteur de boot (512 octets) est trop petit pour marcher toute la FAT. Il fait une seule chose : lire les 3 premiers secteurs d’IO.SYS, en supposant qu’ils commencent au premier cluster de données et se suivent sur le disque. Ensuite ce bout d’IO.SYS (MSLOAD) sait suivre la FAT pour le reste.

Si un fichier ordinaire occupe déjà le début, IO.SYS irait plus loin, fragmenté : le boot ne le trouverait pas. D’où « No room for system files ». FORMAT /S n’a pas ce problème : le volume vient d’être vidé, la place en tête est libre.

SYS A: (page ATTRIB · SYS) fait la même copie sans reformater — utile pour rendre amorçable un disque déjà plein de fichiers, à condition que le début soit encore libre. Sinon SYS échoue, ou déplace des clusters (c’est plus risqué).

COMMAND.COM, lui, n’a pas besoin d’être collé : SYSINIT le charge par son nom, plus tard. On le copie quand même pour que l’invite existe.

The boot sector (512 bytes) is too small to walk the whole FAT. It does one thing: read the first 3 sectors of IO.SYS, assuming they start at the first data cluster and sit next to each other on disk. Then that stub of IO.SYS (MSLOAD) can follow the FAT for the rest.

If an ordinary file already occupies the front, IO.SYS would land further out, fragmented: the boot would not find it. Hence “No room for system files”. FORMAT /S does not have that problem: the volume was just emptied, the front is free.

SYS A: (ATTRIB · SYS page) does the same copy without reformatting — useful to make a disk that already has files bootable, if the front is still free. Otherwise SYS fails, or moves clusters (riskier).

COMMAND.COM need not be contiguous: SYSINIT loads it by name, later. We copy it anyway so the prompt exists.
