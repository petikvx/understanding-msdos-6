IOCTL

TYPE AUTOEXEC.BAT lit des octets sur le disque. MODE CO80 ne lit rien : il dit au pilote d’écran « passe en 80 colonnes ». Ce deuxième genre d’ordre, ce n’est pas un fichier — c’est IOCTL, le service « parler à l’appareil ».

TYPE AUTOEXEC.BAT reads bytes from disk. MODE CO80 reads nothing: it tells the screen driver “go to 80 columns”. That second kind of order is not a file — it is IOCTL, the “talk to the device” service.

Même ticket, autre guichet

DécouverteDiscovery MODE, CTTY, MORE

Quand tu ouvres CON (le clavier/écran) ou A: (une disquette), DOS te donne un numéro — le même genre de « handle » que pour un fichier. Lire et écrire passent par ce numéro. IOCTL aussi : « ce handle, c’est quoi ? un fichier ou le clavier ? » / « mets-le en 80 colonnes » / « cette disquette est un 1.44 Mo ».

Tu ne tapes pas « IOCTL » à l’invite. MODE, CTTY, MORE, FORMAT, DISKCOPY le font pour toi. Pour DOS, tout ça est l’appel n° 44h.

When you open CON (keyboard/screen) or A: (a floppy), DOS gives you a number — the same kind of “handle” as for a file. Read and write go through that number. So does IOCTL: “what is this handle? a file or the keyboard?” / “switch to 80 columns” / “this floppy is 1.44 MB”.

You do not type “IOCTL” at the prompt. MODE, CTTY, MORE, FORMAT, DISKCOPY do it for you. To DOS it is all call 44h.

IntermédiaireIntermediate table de saut 1990

HKN (12/3/90) a remplacé une forêt de CMP par une jump table. AL=0 : get device info (bits CON, CLOCK, NUL…). AL=1 : set. AL=2/3 : caractères de contrôle. AL=0Dh/0Eh : generic block.

HKN (12 Mar 90) replaced a forest of CMPs with a jump table. AL=0: get device info (CON, CLOCK, NUL bits…). AL=1: set. AL=2/3: control chars. AL=0Dh/0Eh: generic block.

TechniqueTechnical ioctl.inc bits

Catégorie : bit 7 = user-defined. Fonction : bit 7 = ignorer si inconnu, bit 6 = intercepté par DOS vs passé au driver, bit 5 = query vs send. AN003 : les sous-fonctions 43h/63h… se marchaient dessus avec OS/2.

Category: bit 7 = user-defined. Function: bit 7 = ignore if unknown, bit 6 = intercepted by DOS vs passed to the driver, bit 5 = query vs send. AN003: subfunctions 43h/63h… collided with OS/2.

Clavier ou fichier ?

DécouverteDiscovery DIR > PRN

DIR > LIST.TXT écrit un fichier. DIR > PRN envoie la même chose à l’imprimante. Pour COMMAND, les deux sont un handle. IOCTL sert à demander : fichier sur la FAT, ou CON / PRN ? MORE s’en sert pour paginer (écran) ou tout déverser (fichier).

DIR > LIST.TXT writes a file. DIR > PRN sends the same bytes to the printer. To COMMAND both are a handle. IOCTL asks: FAT file, or CON / PRN? MORE uses that to page (screen) or dump everything (file).

IntermédiaireIntermediate raw / cooked

devid_device_raw : plus de Ctrl-C / tab / echo sur CON. Les programmes plein écran passent en raw. CHARHARD (INT 24 caractère) en dépend.

devid_device_raw: no more Ctrl-C / tab / echo on CON. Full-screen programs go raw. CHARHARD (character INT 24) depends on it.

Dire au lecteur « cette disquette est un 1.44 »

DécouverteDiscovery Changer de format de disquette sans FORMAT Change floppy format without FORMAT

Lire un fichier ne dit rien de la géométrie (80 pistes ? 18 secteurs ?). FORMAT et DISKCOPY doivent l’annoncer au pilote. Ils n’appellent pas le BIOS tout seuls : ils envoient un paquet IOCTL. Le pilote comprend « prépare cette géométrie ».

Reading a file says nothing about geometry (80 tracks? 18 sectors?). FORMAT and DISKCOPY must tell the floppy driver. They do not call the BIOS themselves: they send an IOCTL packet. The driver understands “prepare this geometry”.

IntermédiaireIntermediate multi-track · AN001

DOS 4 ajoute le formatage / verify multi-pistes. AN002 : disques durs jamais formatés. Le BPB renvoyé alimente le DPB (page FAT).

DOS 4 adds multi-track format / verify. AN002: never-formatted hard disks. The returned BPB feeds the DPB (FAT page).

TechniqueTechnical $IOCTL créé ARR 4 Apr 1983

Même date que beaucoup du noyau 2.x (alloc, exec). IOCTL est l’autre face de INT 21h : pas un fichier, un appareil.
