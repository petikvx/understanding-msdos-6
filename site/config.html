bios/sysconf.asm · sysinit1.asm

CONFIG.SYS

Le fichier que SYSINIT lit pour fabriquer votre DOS : combien de SFT (FILES=), quels pilotes, le DOS en HMA ou non. Ce n’est pas COMMAND.COM qui le lit — le noyau n’est même pas encore « fini ».

The file SYSINIT reads to build your DOS: how many SFTs (FILES=), which drivers, DOS in the HMA or not. COMMAND.COM does not read it — the kernel is not even “finished” yet.

Plusieurs passes Several passes

DécouverteDiscovery L’ordre compte, et on relit Order matters, and we reread

On ne peut pas charger HIMEM après s’être déjà installé en bas. SYSINIT parcourt CONFIG plusieurs fois : d’abord les directives qui décident où vit DOS, ensuite les DEVICE=, puis le reste. D’où les menus multi-config de DOS 6 (MULTI_CONFIG).

You cannot load HIMEM after already installing low. SYSINIT walks CONFIG several times: first the lines that decide where DOS lives, then DEVICE=, then the rest. Hence DOS 6’s multi-config menus (MULTI_CONFIG).

IntermédiaireIntermediate FILES · BUFFERS · LASTDRIVE · INSTALL

FILES= agrandit la SFT (page Fichiers). BUFFERS= le cache de buf.asm. LASTDRIVE= les CDS. INSTALL= lance un programme via EXEC pendant SYSINIT, avec un environnement volontairement NULL (M067) — pas encore de COMSPEC fiable.

FILES= grows the SFT (Files page). BUFFERS= is the buf.asm cache. LASTDRIVE= the CDS. INSTALL= runs a program via EXEC during SYSINIT, with a deliberately NULL environment (M067) — no reliable COMSPEC yet.

DEVICE= · overlay

DécouverteDiscovery Un programme sans PSP A program with no PSP

Un pilote n’est pas FOO.COM. SYSINIT le charge comme overlay ($EXEC AL=3) : pas de PSP, pas d’environnement, une adresse et un facteur de reloc. Puis il appelle la stratégie d’init du driver.

A driver is not FOO.COM. SYSINIT loads it as an overlay ($EXEC AL=3): no PSP, no environment, an address and a reloc factor. Then it calls the driver’s init strategy.

IntermédiaireIntermediate DEVICEHIGH · UMB

GetUMBForDev / SpaceInUMB? : si les UMB sont liées, on essaie de loger le pilote en haut. LieInt12Mem ment à INT 12h pour que le driver croie qu’il n’y a que 640 Ko — sinon certains s’installent trop bas tous seuls.

GetUMBForDev / SpaceInUMB?: if UMBs are linked, we try to house the driver high. LieInt12Mem lies to INT 12h so the driver thinks there are only 640 KB — otherwise some install themselves too low.

TechniqueTechnical ExecDev

bios/sysconf.asm

InitDevLoad / SizeDevice
ExecDev                 ; $EXEC overlay
DevSetBreak             ; taille résidente

Après init, on « casse » l’arène à la taille que le driver a rendue — le reste redevient libre. Même idée que le TSR, sans PSP.

After init we “break” the arena at the size the driver returned — the rest is free again. Same idea as a TSR, no PSP.

DOS=HIGH,UMB

DécouverteDiscovery Mettre le noyau au-dessus de 1 Mo Put the kernel above 1 MB

La HMA est le premier segment de 64 Ko au-delà de 1 Mo, visible seulement si la ligne A20 est allumée. HIMEM la donne à DOS ; DOS=HIGH y loge le noyau. UMB enchaîne les trous 640K–1M à l’arène (page Mémoire).

The HMA is the first 64 KB segment past 1 MB, visible only if the A20 line is on. HIMEM gives it to DOS; DOS=HIGH parks the kernel there. UMB links the 640K–1M holes into the arena (Memory page).

IntermédiaireIntermediate ProcDOS tags 1–4

Le parseur rend un tag : 1 HIGH, 2 LOW, 3 UMB, 4 NOUMB. On peut combiner DOS=HIGH,UMB. Sans HIMEM chargé d’abord, HIGH échoue silencieusement et DOS reste bas.

The parser yields a tag: 1 HIGH, 2 LOW, 3 UMB, 4 NOUMB. You can combine DOS=HIGH,UMB. Without HIMEM loaded first, HIGH fails quietly and DOS stays low.

TechniqueTechnical TryToMovDOSHi

M024 : LoadDOSHiOrLow appelle TryToMovDOSHi. M025 : dos_segreinit avant d’allouer le reste. M072 : Power_Init après les stubs HIGH pour qu’il accroche INT 2Fh correctement. Suite : HIMEM.

M024: LoadDOSHiOrLow calls TryToMovDOSHi. M025: dos_segreinit before allocating the rest. M072: Power_Init after the HIGH stubs so it hooks INT 2Fh correctly. Next: HIMEM.
