dev/himem/himem.asm

HIMEM.SYS

Le pilote XMS : il allume et éteint la 21e ligne d’adresse, prête la HMA à DOS, et gère la mémoire au-delà de 1 Mo. Sans lui, les rustines A20OFF_COUNT du noyau n’ont rien à dire au matériel.

The XMS driver: it turns the 21st address line on and off, lends the HMA to DOS, and manages memory past 1 MB. Without it, the kernel’s A20OFF_COUNT patches have nothing to say to the hardware.

XMS

DécouverteDiscovery Un autre INT 21h, pour la RAM lointaine Another INT 21h, for far RAM

Les programmes ne touchent pas à l’extended memory tout seuls (le mode réel s’arrête à 1 Mo + HMA). Ils demandent à HIMEM, via INT 2Fh puis un point d’entrée XMS : allouer un bloc, le copier, le rendre.

Programs do not touch extended memory by themselves (real mode stops at 1 MB + HMA). They ask HIMEM, via INT 2Fh then an XMS entry point: allocate a block, copy it, free it.

IntermédiaireIntermediate himem4 · himem5

Le fichier d’en-tête découpe le travail : himem1 commutation A20, himem2 init, himem4 allocation, himem5 copie (souvent INT 15h block move). Windows 3.x exige que ce HIMEM soit plus récent que celui de Compaq (2.50) — d’où le saut à 2.60.

The header splits the work: himem1 A20 switching, himem2 init, himem4 allocation, himem5 copy (often INT 15h block move). Windows 3.x wants this HIMEM newer than Compaq’s (2.50) — hence the jump to 2.60.

TechniqueTechnical 16 Mo EISA

2.50 : ignorer la mémoire « super-extended » des cartes EISA au-delà de 16 Mo. Les descripteurs 24 bits (80286) ne savent pas adresser plus loin. I070 : contourner le block move INT 15h sur certaines machines (Tortugas, 30-286).

2.50: ignore “super-extended” memory on EISA boards past 16 MB. 24-bit (80286) descriptors cannot reach further. I070: skip the INT 15h block move on some machines (Tortugas, 30-286).

A20

DécouverteDiscovery Le fil qui fait le wrap 8086 The wire that makes the 8086 wrap

Sur un 8086, FFFF:0010 retombe en 0000:0000. Les applis copy-protected testent ça. Sur un 286+, la 21e ligne (A20) si elle est à 1 donne plutôt la HMA. HIMEM doit donc parfois éteindre A20 — d’où A20OFF_COUNT dans LeaveDos et EXEC.

On an 8086, FFFF:0010 wraps to 0000:0000. Copy-protected apps test that. On a 286+, the 21st line (A20) if high yields the HMA instead. HIMEM must therefore sometimes turn A20 off — hence A20OFF_COUNT in LeaveDos and EXEC.

IntermédiaireIntermediate /A20CONTROL:ON|OFF

Par défaut HIMEM prend le contrôle d’A20 même si elle était déjà allumée (2.50). OFF : ne pas y toucher si elle l’était. 2.37 : retiré un « fix » Chargecard qui empêchait de re-didler A20 après deux sessions Windows réel (Global enable/disable).

By default HIMEM takes A20 even if it was already on (2.50). OFF: leave it alone if it was on. 2.37: removed a Chargecard “fix” that stopped us diddling A20 after two real-mode Windows sessions (Global enable/disable).

TechniqueTechnical Toshiba 1600

2.60 ajoute une routine A20 spéciale pour le portable Toshiba 1600. IsA20On a été allégé (2.35). Plusieurs machines = plusieurs ports (PS/2, AT, Hornet…) dans himem1.asm.

2.60 adds a special A20 routine for the Toshiba 1600 laptop. IsA20On was slimmed (2.35). Many machines = many ports (PS/2, AT, Hornet…) in himem1.asm.

HMA

DécouverteDiscovery 64 Ko pour un seul client 64 KB for a single client

La spec XMS : la HMA va à un demandeur (souvent DOS lui-même via DOS=HIGH). Pas de sous-allocation. C’est pour ça que COMMAND et les buffers restent souvent en bas.

The XMS spec: the HMA goes to one claimant (often DOS itself via DOS=HIGH). No sub-allocation. That is why COMMAND and buffers often stay low.

IntermédiaireIntermediate DEVICE=HIMEM.SYS en premier

SYSINIT (page CONFIG) a besoin de HIMEM avant de déplacer DOS. D’où l’ordre canonique : DEVICE=HIMEM.SYS puis DOS=HIGH puis EMM386 / DEVICEHIGH.

SYSINIT (CONFIG page) needs HIMEM before moving DOS. Hence the canonical order: DEVICE=HIMEM.SYS then DOS=HIGH then EMM386 / DEVICEHIGH.

TechniqueTechnical Flush · bit 15

Si le driver est « flushed » (non chargé), on descend le bit 15 des attributs d’en-tête — l’Encyclopedia MS-DOS le demande (commentaire 2.60). Lien avec le noyau : ChkCopyProt / EXECA20OFF dans msproc.asm.

If the driver is “flushed” (not kept), bit 15 of the header attributes is cleared — the MS-DOS Encyclopedia says so (2.60 comment). Kernel link: ChkCopyProt / EXECA20OFF in msproc.asm.
