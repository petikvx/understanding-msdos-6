FAT

File Allocation Table : le plan que MS-DOS 6 tient de chaque disque. Cette page décrit comment le système découpe un volume, enchaîne les clusters, nomme les fichiers et les retrouve — du usage quotidien jusqu’aux routines assembleur du noyau, illustrées champ par champ et ligne par ligne.

File Allocation Table: the map MS-DOS 6 keeps of every disk. This page follows how the system lays out a volume, chains clusters, names files and finds them again — from everyday use down to the kernel’s assembly routines, illustrated field by field and line by line.

Qu’est-ce que FAT What FAT is

Découverte Discovery Un plan du disque, case par case A map of the disk, cell by cell

Imaginez un parking numéroté. Un fichier n’occupe pas forcément des places côte à côte : il peut commencer à la place 12, continuer à la 47, puis finir à la 48. La table d’allocation (FAT) est le panneau qui indique, pour chaque place, « suivante = 47 », « suivante = 48 », ou « fin de fichier ».

MS-DOS 6 utilise ce plan pour presque tout ce que vous stockez : programmes, documents, et même les dossiers (sauf la racine C:\, qui a un emplacement fixe). Quand vous tapez DIR, le système lit d’abord l’annuaire, puis suit ces chaînes pour savoir où sont les octets.

Think of a numbered car park. A file does not have to sit in adjacent bays: it may start at bay 12, continue at 47, and finish at 48. The File Allocation Table is the board that says, for each bay, “next = 47”, “next = 48”, or “end of file”.

MS-DOS 6 uses this map for almost everything you store: programs, documents, and even folders (except the root C:\, which has a fixed home). When you type DIR, the system first reads the directory, then follows those chains to find the bytes.

Intermédiaire Intermediate FAT12 et FAT16, pas FAT32 FAT12 and FAT16, not FAT32

MS-DOS 6 connaît deux largeurs d’entrée : FAT12 (12 bits, disquettes et très petits volumes) et FAT16 (16 bits, disques durs). FAT32 n’existe pas encore : il arrivera avec Windows 95 OSR2.

Chaque entrée de la table peut valoir :

  • 0000 — cluster libre ;
  • un numéro entre 2 et le dernier cluster — « le suivant est celui-ci » ;
  • une valeur d’end of file (fin de chaîne) ;
  • une marque de secteur défectueux.

DOS choisit 12 ou 16 bits d’après le nombre de clusters du volume, pas d’après une étiquette « FAT12 » écrite quelque part. Au-delà d’environ 4086 clusters, le noyau bascule en 16 bits.

MS-DOS 6 understands two entry widths: FAT12 (12 bits, floppies and very small volumes) and FAT16 (16 bits, hard disks). FAT32 does not exist yet; it arrives with Windows 95 OSR2.

Each table entry may be:

  • 0000 — a free cluster;
  • a number between 2 and the last cluster — “the next one is this”;
  • an end of file value (end of the chain);
  • a bad-sector mark.

DOS picks 12 or 16 bits from the volume’s cluster count, not from a “FAT12” label written somewhere. Past roughly 4086 clusters, the kernel switches to 16 bits.

Anatomie d’un volume Anatomy of a volume

Découverte Discovery Cinq zones, toujours dans le même ordre Five zones, always in the same order

Un disque formaté par MS-DOS n’est pas un tas d’octets indifférencié. Il commence par un secteur d’amorçage (qui décrit le reste), puis une ou deux copies de la table FAT, puis l’annuaire de la racine, puis enfin la grande zone de données où vivent les fichiers.

A disk formatted by MS-DOS is not an undifferentiated heap of bytes. It starts with a boot sector (which describes the rest), then one or two copies of the FAT, then the root directory, and finally the large data area where files live.

Boot FAT 1 FAT 2 Root Data
Intermédiaire Intermediate Le BPB, carte d’identité du disque The BPB, the disk’s identity card

Le BIOS Parameter Block (BPB) est une structure posée juste après le saut d’amorçage. Il mélange volontairement géométrie physique (secteurs/piste, têtes) et organisation FAT (nombre de FAT, taille d’un cluster, nombre d’entrées racine).

BPB_TOTALSECTORS est un mot 16 bits : au-delà de 32 Mo, DOS 4+ met ce champ à zéro et utilise BPB_BIGTOTALSECTORS (32 bits). C’est le format « huge » que MS-DOS 6 hérite et que FDISK étiquette parfois type de partition 6.

The BIOS Parameter Block (BPB) sits just after the boot jump. It deliberately mixes physical geometry (sectors/track, heads) with FAT layout (FAT count, cluster size, root-entry count).

BPB_TOTALSECTORS is a 16-bit word: past 32 MB, DOS 4+ zeroes that field and uses BPB_BIGTOTALSECTORS (32 bits). That is the “huge” format MS-DOS 6 inherits, which FDISK sometimes labels as partition type 6.

Clusters

Découverte Discovery La plus petite « case » d’un fichier The smallest “bay” a file can occupy

Un cluster (unité d’allocation) est un groupe de secteurs consécutifs. C’est la plus petite quantité que DOS peut donner à un fichier. Un fichier d’un seul octet prend donc un cluster entier — sur un gros disque, parfois 16 ou 32 Ko. C’est pour cela que beaucoup de tout petits fichiers « mangent » plus de place que leur taille affichée par DIR.

A cluster (allocation unit) is a group of consecutive sectors. It is the smallest amount DOS can give a file. A one-byte file therefore takes a whole cluster — on a large disk, sometimes 16 or 32 KB. That is why many tiny files “eat” more space than the size DIR shows.

Intermédiaire Intermediate Le premier cluster utile porte le numéro 2 The first useful cluster is number 2

Les clusters 0 et 1 sont réservés (descripteur média et drapeaux). Les données commencent au cluster 2, juste après la racine. La conversion usuelle est :

secteur = premier_secteur_données + (cluster − 2) × secteurs_par_cluster

Le DPB stocke déjà sectors/cluster − 1 (dpb_cluster_mask) et log₂(sectors/cluster) (dpb_cluster_shift), pour remplacer les multiplications par des décalages.

Clusters 0 and 1 are reserved (media descriptor and flags). Data starts at cluster 2, right after the root. The usual conversion is:

sector = first_data_sector + (cluster − 2) × sectors_per_cluster

The DPB already stores sectors/cluster − 1 (dpb_cluster_mask) and log₂(sectors/cluster) (dpb_cluster_shift), so multiplies become shifts.

L’inverse — secteur vers couple (cluster, index dans le cluster) — est dans DirRead (dos/disk.asm). La racine est un cas à part : DIRStart = 0, et « cluster » y signifie en réalité « toute la racine ».

La table d’allocation The allocation table

Découverte Discovery Suivre la chaîne Following the chain

L’entrée de répertoire d’un fichier ne contient pas la liste de tous ses clusters : seulement le premier. Pour lire la suite, DOS ouvre la FAT à cette case, y lit le numéro suivant, et ainsi de suite jusqu’à une marque de fin.

A file’s directory entry does not list every cluster — only the first. To read the rest, DOS opens the FAT at that cell, reads the next number, and so on until an end mark.

DIR_FIRST = 12 → UNPACK 12 → 47 → UNPACK 47 → 48 → IsEOF 48 ?

Intermédiaire Intermediate 12 bits à cheval, 16 bits alignés 12 bits straddling, 16 bits aligned

En FAT16, chaque entrée tient dans un mot : offset = cluster × 2. En FAT12, une entrée fait un octet et demi. Deux clusters voisins partagent trois octets, et une entrée impaire occupe les 12 bits de poids fort. Pire : ces trois octets peuvent chevaucher la frontière de deux secteurs.

Il y a presque toujours deux copies de la FAT. Si l’une est illisible, CHKDSK et le noyau tentent l’autre. Les deux doivent rester identiques après chaque allocation.

In FAT16 each entry is a word: offset = cluster × 2. In FAT12 an entry is one and a half bytes. Two neighbouring clusters share three bytes, and an odd entry occupies the high 12 bits. Worse: those three bytes can straddle a sector boundary.

There are almost always two copies of the FAT. If one is unreadable, CHKDSK and the kernel try the other. Both must stay identical after every allocation.

Technique Technical UNPACK · PACK · MAPCLUSTER

Tout accès à une entrée passe par dos/fat.asm.

  • MAPCLUSTER calcule l’offset (cluster + cluster/2 en FAT12, 2 × cluster en FAT16), divise par la taille de secteur (raccourci si 512 octets), et ramène le secteur via GETBUFFRB.
  • Si l’entrée est à cheval, CLUSSPLIT est posé et les deux moitiés sont rassemblées dans CLUSSAVE.
  • UNPACK lit ; PACK écrit en préservant le nibble voisin en FAT12, puis marque le tampon buf_dirty.
  • Le cluster 0 n’est jamais lu sur disque (correctif M014) : la valeur vit dans CL0FATENTRY.

Every access to an entry goes through dos/fat.asm.

  • MAPCLUSTER computes the offset (cluster + cluster/2 on FAT12, 2 × cluster on FAT16), divides by the sector size (fast path if 512 bytes), and brings the sector in with GETBUFFRB.
  • If the entry straddles a boundary, CLUSSPLIT is set and the two halves are gathered in CLUSSAVE.
  • UNPACK reads; PACK writes, preserving the neighbouring nibble on FAT12, then marks the buffer buf_dirty.
  • Cluster 0 is never read from disk (fix M014): the value lives in CL0FATENTRY.

Répertoire et attributs Directory and attributes

Découverte Discovery Un nom 8.3 et quelques drapeaux An 8.3 name and a few flags

La racine est un annuaire de taille fixe, créé au formatage. Chaque fichier ou dossier y (ou dans un sous-dossier) a une fiche : un nom d’au plus 8 caractères, une extension d’au plus 3, des attributs (lecture seule, caché, système, archive), une date de dernière écriture, et le numéro du premier cluster.

La commande ATTRIB change ces drapeaux. DIR /A les utilise pour filtrer l’affichage. Un dossier n’est qu’un fichier un peu spécial, dont le contenu est une liste d’autres fiches — sauf la racine, qui n’est pas un fichier.

The root is a fixed-size directory, created at format time. Every file or folder there (or in a subfolder) has a card: a name of at most 8 characters, an extension of at most 3, attributes (read-only, hidden, system, archive), a last-write date, and the first-cluster number.

The ATTRIB command changes those flags. DIR /A uses them to filter the listing. A folder is just a slightly special file whose contents are more cards — except the root, which is not a file.

Intermédiaire Intermediate 32 octets, date empaquetée, cases libres 32 bytes, packed date, free slots

Chaque entrée fait exactement 32 octets. Le premier octet du nom vaut E5h si la case est libre (fichier effacé), et 00h si aucune entrée n’a jamais été écrite plus loin — DOS peut alors arrêter le parcours.

L’heure tient dans un mot : bits 0–4 = secondes/2, 5–10 = minutes, 11–15 = heures. La date : bits 0–4 = jour, 5–8 = mois, 9–15 = année − 1980. Un dossier hors racine a les attributs 10h et une taille affichée à zéro : son « fichier » est la chaîne de clusters de l’annuaire.

Each entry is exactly 32 bytes. The first byte of the name is E5h if the slot is free (deleted file), and 00h if nothing has ever been written further along — DOS can then stop scanning.

Time fits in a word: bits 0–4 = seconds/2, 5–10 = minutes, 11–15 = hours. Date: bits 0–4 = day, 5–8 = month, 9–15 = year − 1980. A non-root folder has attribute 10h and a displayed size of zero: its “file” is the directory’s cluster chain.

Cycle de vie d’un fichier A file’s life cycle

Découverte Discovery Créer, grandir, effacer Create, grow, delete

Créer un fichier, c’est réserver une fiche dans un annuaire et, dès qu’on écrit, prendre un premier cluster. Agrandir le fichier, c’est accrocher d’autres clusters à la chaîne. Effacer, c’est marquer la fiche comme libre (le nom commence alors par un « σ » visuel, en réalité l’octet E5) et rendre les clusters au réservoir. Les octets eux-mêmes restent sur le disque jusqu’à ce qu’un autre fichier les réutilise — d’où les utilitaires de « undelete ».

Creating a file means reserving a directory slot and, as soon as you write, taking a first cluster. Growing the file means hanging more clusters on the chain. Deleting means marking the slot free (the name then starts with a visual “σ”, actually the byte E5) and returning the clusters to the pool. The bytes themselves stay on disk until another file reuses them — hence “undelete” utilities.

Intermédiaire Intermediate Fragmentation et clusters perdus Fragmentation and lost clusters

DOS alloue en général le premier cluster libre qu’il trouve en balayant à partir du dernier alloué. Si le disque a déjà servi, la chaîne d’un fichier n’est plus contiguë : c’est la fragmentation. La lecture reste correcte (on suit la FAT) mais plus lente.

Si un programme s’arrête au milieu d’une écriture, des clusters peuvent rester marqués occupés sans appartenir à aucune fiche : CHKDSK les signale comme « lost clusters » et propose de les rassembler dans des fichiers FILE0000.CHK.

DOS usually allocates the first free cluster it finds, scanning from the last one it gave out. Once the disk has been used, a file’s chain is no longer contiguous: that is fragmentation. Reads stay correct (the FAT is followed) but slower.

If a program dies mid-write, clusters can stay marked busy without belonging to any directory slot: CHKDSK reports them as “lost clusters” and offers to gather them into FILE0000.CHK files.

ALLOCATE (dos/rom.asm) starts at dpb_next_free and walks forward. If it hits the end of the disk without success and did not start at 2, it restarts from cluster 2. If it was already starting at 2, the disk is full (insufficient_disk_space).

BPB, DPB et tampons BPB, DPB and buffers

Découverte Discovery DOS se souvient de chaque lecteur DOS remembers each drive

Relire le secteur d’amorçage à chaque TYPE FICHIER.TXT serait trop lent. DOS garde en mémoire une fiche par lecteur logique (A:, B:, C:…) : taille des secteurs, endroit de la FAT, nombre de clusters libres. C’est cette fiche qu’il consulte en permanence.

Re-reading the boot sector on every TYPE FILE.TXT would be too slow. DOS keeps an in-memory card per logical drive (A:, B:, C:…): sector size, where the FAT lives, how many clusters are free. That card is what it consults all the time.

Intermédiaire Intermediate BPB → DPB

Le BPB est sur le disque. Le DPB (Drive Parameter Block) en est la copie de travail, allouée au démarrage et chaînée depuis DPBHead. Un changement de disquette doit invalider cette copie : FATREAD_CDS / FATREAD_SFT interrogent le pilote (« le média a-t-il changé ? ») et, le cas échéant, reconstruisent le DPB et jettent les tampons du lecteur.

Les secteurs récemment lus (FAT, répertoires, données) vivent dans un cache de tampons. Un tampon modifié est marqué dirty et sera réécrit, souvent en deux exemplaires pour la FAT.

The BPB lives on disk. The DPB (Drive Parameter Block) is the working copy, allocated at boot and chained from DPBHead. A floppy change must invalidate that copy: FATREAD_CDS / FATREAD_SFT ask the driver (“has the media changed?”) and, if so, rebuild the DPB and drop that drive’s buffers.

Recently read sectors (FAT, directories, data) live in a buffer cache. A modified buffer is marked dirty and will be written back, often twice for the FAT.

Pas de longs noms (ils arriveront avec Windows 95, sous forme d’entrées empilées). Pas de FAT32 : un volume FAT16 est plafonné à 2 Go, et au-delà de quelques centaines de mégaoctets les clusters deviennent gros, donc gaspilleurs. La racine a un nombre d’entrées fixé au formatage (souvent 512 sur un disque dur) : on peut « remplir C:\ » sans avoir rempli le disque.

DoubleSpace / DriveSpace (compression) se greffe au-dessus de FAT : le noyau continue de voir des clusters ; le pilote comprime les données réelles. ALLOCATE porte même un point d’ancrage MAGICPATCH pour refuser une allocation si le FAT dit « oui » mais que l’espace comprimé dit « non ».

No long names (they arrive with Windows 95, as stacked entries). No FAT32: a FAT16 volume tops out at 2 GB, and past a few hundred megabytes clusters become large and wasteful. The root has an entry count fixed at format time (often 512 on a hard disk): you can “fill C:\” without filling the disk.

DoubleSpace / DriveSpace (compression) sits on top of FAT: the kernel still sees clusters; the driver compresses the real data. ALLOCATE even has a MAGICPATCH hook so allocation can fail when the FAT says “yes” but the compressed free space says “no”.

Technique Technical FORMAT · CHKDSK · FATSECRD

Les utilitaires vivent sous cmd/ : format, chkdsk, fdisk, recover, attrib, sys. Les messages d’erreur FAT sont centralisés dans h/utilmid.h (MSG_CHK_BAD_FAT, MSG_CHK_LOST_CLUSTERS, MSG_CHK_INV_CLUSTER, MSG_FMT_FAT_ERROR…).

FATSECRD (dos/disk.asm) relit un secteur de FAT en essayant chaque copie (dpb_FAT_count). Il force HIGH_SECTOR = 0 : le code suppose encore que les secteurs de la FAT elle-même tiennent sous la barre des 32 Mo — vrai pour un volume FAT16 classique, où la table reste près du début du disque.
